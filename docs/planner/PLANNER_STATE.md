# AI Planner State Management (`plannerStore.ts`)

The AI Planner feature uses a centralized Nanostore (`src/components/planner/stores/plannerStore.ts`) to manage the application state, ensuring reactivity across the complex UI components.

## 1. State Structure (`PlannerState`)

The store holds all volatile and persistent settings related to the current planning session.

| State Field | Type | Description |
| :--- | :--- | :--- |
| `userPrompt` | `string` | The natural language instruction provided by the user. |
| `currentPlanId` | `string \| null` | The ID of the currently loaded plan (persisted in DB). |
| `plan` | `IPlan \| null` | The complete, structured plan object generated by the AI. |
| `isLoading` | `boolean` | True when awaiting a response from the `generatePlan` API. |
| `error` | `string \| null` | Error message related to plan generation failure. |
| **`applyStatus`** | `'idle' \| 'applying' \| 'success' \| 'failure'` | Status of the entire plan application process. |
| **`applyError`** | `string \| null` | Error message if plan application fails. |
| `projectRoot` | `string` | The absolute path to the project root directory. Synchronized with `fileTreeStore`. |
| `scanPathsInput` | `string` | Comma-separated string of relative paths for AI context scanning. |
| `additionalInstructions` | `string` | The customized LLM system prompt (Markdown content). |
| `expectedOutputFormat` | `string` | The customized JSON schema or output format definition. |
| `fileData` | `string \| null` | Base64 encoded data of an attached multimodal file (e.g., image). |
| `fileMimeType` | `string \| null` | MIME type of the attached file. |

## 2. Key Actions

The store exposes actions to safely mutate the state, often triggering complex side effects (like loading a plan from the API).

*   `setUserPrompt(prompt: string)`: Updates the user instruction text.
*   `setPlan(planId: string \| null, plan: IPlan \| null)`: Sets the generated/loaded plan, resets loading flags, and clears generation errors. Crucially, it resets `applyStatus` to `'idle'`.
*   `loadPlanById(planId: string)`: Asynchronous action that fetches a stored plan using `plannerService`.
*   `setApplyStatus(status: PlannerState['applyStatus'], error?: string)`: Updates the application status and related error messages.
*   `updateCurrentPlanMetadata(updatedMetadata: Partial<IPlan>)`: Allows editing core plan fields (title, confidence, git instructions) locally before application.
*   `updateFileChange(planId: string, changeIndex: number, updatedChange: IFileChange)`: Updates a single item in the `plan.changes` array. This also resets `applyStatus` to `'idle'`.
*   `setPlannerProjectRoot(root: string)`: Updates the `projectRoot` field.
*   `setScanPathsInput(paths: string)`: Updates the comma-separated scan paths string.
*   `resetPlannerState()`: Resets all core fields to their initial defaults, including context paths and instructions.

## 3. Synchronization with `fileTreeStore`

The `projectRoot` is a shared concept:
1.  `projectRootDirectoryStore` (from `fileTreeStore`) manages the globally persistent user-selected root path.
2.  `plannerStore.projectRoot` mirrors this value and is used in API payloads.

Changes to the global `projectRootDirectoryStore` (e.g., via the File Explorer UI) automatically update `plannerStore.projectRoot` upon initialization or specific component effects (`PlanGenerator.tsx`).
